Abstract - Operational systems are required to support large-scale distributed computation as well as low latency responses at user interaction points. We argue that these requirements make current stateful databases unsuitable for use on operational workloads due both to concerns about consistency as they scale up [Gilbert et al., 11] as well as the high level of complexity that their maintenance demands [Wilkes et al., 17]. Furthermore, current approaches based around replication overlaying existing relational database technologies do not fit operationally [Stonebraker et al., 17], instead requiring careful partitioning by application developers, thus requiring deep understanding of each application's behaviour. In this position paper we propose an operating system-level data management approach to address these problems. By using new concurrency control techniques along with persistent storage and log collection across processes, we would ensure consistent views that reflect all processes at any time. This has the advantage if ensuring correctness independent of application developer decisions or implementation details since it will automatically handle partitioned transactional operations across multiple components without additional special handling by either applications or infrastructure services
